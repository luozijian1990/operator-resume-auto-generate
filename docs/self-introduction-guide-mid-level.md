# 中级运维 / SRE 自我介绍指南

> 中级岗位的自我介绍，核心已经不只是“我做过什么”，而是要让面试官看到：你能够独立承担一块工作，对结果负责，并且开始形成自己的问题解决方式。

本文适用于运维、DevOps、SRE、平台工程、云原生等方向，通常适合约 3～5 年工作经验，或者已经能够独立负责项目、模块和线上问题的候选人。

## 一、中级岗位和初级岗位最大的区别

初级岗位主要证明：

> 我能完成事情。

中级岗位需要进一步证明：

> **我能够独立把一件事情做成。**

这里的“做成”通常意味着：

- 能理解需求和背景；
- 能拆解任务；
- 能选择合适方案；
- 能独立实施；
- 能处理过程中出现的问题；
- 能验证结果；
- 能复盘并沉淀经验；
- 必要时能推动其他人协作完成。

所以中级岗位自我介绍的核心可以概括为：

> **独立负责是主线，项目是证据，方法沉淀是结论。**

## 二、中级岗位已经可以讲成长，但不要讲得过于宏大

中级候选人通常已经经历过明显的能力变化。

例如：

```text
完成任务
  ↓
独立解决问题
  ↓
独立负责项目
  ↓
开始做自动化 / 标准化
```

这已经可以形成一条简单的职业成长主线。

但通常没有必要像高级岗位一样拆成五六个职业阶段。

更适合的是：

> **用 2～3 个关键变化说明自己是怎么从执行者成长为独立负责人的。**

例如：

```text
第一阶段：把基础运维工作做扎实
第二阶段：开始独立负责核心业务
第三阶段：把重复问题做成自动化和标准化
```

这里的重点不是阶段名称，而是：

> 每一次变化以后，你承担的问题是不是更复杂了。

## 三、中级岗位推荐结构

可以使用下面这条主线：

```text
职业定位
  ↓
独立负责的业务 / 系统
  ↓
代表性项目
  ↓
复杂问题处理
  ↓
自动化 / 标准化 / 改进
  ↓
当前发展方向
```

### 1. 职业定位

先让面试官快速知道你的主要能力方向。

例如：

> 我目前主要负责 Kubernetes、发布体系和可观测性相关工作，平时既承担核心业务的日常稳定性保障，也会做一些自动化和平台化改进。

这一句已经比单纯列技术栈多了一层“工作角色”。

### 2. 独立负责范围

中级岗位最好明确说明：

> 你到底独立负责过什么。

例如：

- 一个核心业务；
- 一个 Kubernetes 集群；
- CI/CD 体系；
- 监控告警；
- 日志平台；
- 某类中间件；
- 一个内部运维平台。

重点不是规模一定很大，而是：

> 你是不是主要责任人之一。

### 3. 代表性项目

挑 1～2 个能证明独立能力的项目。

重点讲：

```text
为什么做
→
有什么约束
→
你怎么判断
→
怎么实施
→
最后效果如何
```

中级岗位已经不能只回答“按领导要求执行”。

面试官会开始关注：

> 为什么这么做？

### 4. 复杂问题处理

中级岗位通常应该能独立处理线上问题。

因此可以适当提到：

- 故障定位；
- 性能问题；
- 网络问题；
- 发布问题；
- 容量问题；
- 中间件问题。

重点体现：

> 你已经形成了相对稳定的排查思路。

### 5. 自动化和标准化

这是初级到中级很典型的分界点。

中级候选人不应该长期停留在：

> 每次遇到问题都重新人工处理。

而应该开始思考：

```text
这个问题为什么重复发生？
能不能自动化？
能不能标准化？
能不能加监控？
能不能形成 SOP？
```

这类内容非常适合放进自我介绍。

## 四、中级岗位应该开始体现“为什么”

初级候选人能说清楚：

> 我做了什么。

通常已经不错。

中级候选人还应该进一步讲：

> **为什么这么做。**

例如：

较弱：

> 我们使用 Prometheus 做监控。

更好：

> 原来的监控主要关注主机层，业务出现问题以后很难快速判断影响范围，所以后来我们补了 Kubernetes 和应用侧指标，并重新梳理了一部分告警规则。

这里体现的已经不只是工具使用，而是：

> 你知道原来的方案为什么不够。

中级岗位应该逐渐从“工具使用者”变成“方案参与者”。

## 五、中级岗位可以体现一定的业务理解

中级岗位不一定要求非常成熟的商业思维，但应该知道：

> 自己维护的系统为什么重要。

例如：

不要只说：

> 我负责物流系统。

可以说：

> 我负责物流仓储相关系统，这块业务对实时性要求比较高，一旦任务积压或者接口异常，很快会影响仓库作业，所以这类问题的告警和恢复速度要求比较高。

这样技术工作就和业务场景连接起来了。

这也是中级和纯执行型候选人的重要区别。

## 六、项目不仅要讲实施，还要讲取舍

到了中级岗位，面试官会开始关注：

> 你为什么选择方案 A，不选择方案 B？

不一定要求非常复杂的架构设计，但至少应该体现基本 trade-off。

例如：

- 为什么用 Deployment 而不是 StatefulSet；
- 为什么选择滚动发布；
- 为什么保留人工审批；
- 为什么先做脚本而不是直接建设平台；
- 为什么告警阈值这样设置；
- 为什么某些服务上云，某些暂时保留 IDC。

只要是真实做过的判断，都可以成为中级岗位的重要证据。

## 七、从“解决问题”开始走向“减少问题”

中级岗位很适合讲这样一类成长：

```text
最开始：
出了问题我去解决

后来：
我开始总结问题

再后来：
我通过自动化、监控、SOP、平台能力
减少同类问题重复发生
```

这通常是非常自然的能力升级。

例如：

> 前期我主要处理线上故障，后来发现很多问题其实是重复出现的，所以开始把排查步骤做成脚本，把常见场景补到监控和 SOP 里，减少对个人经验的依赖。

这段话非常符合中级岗位定位。

它既没有夸大到组织能力，也已经超出了单纯执行。

## 八、中级岗位的 Hook 怎么设计

中级岗位可以比初级岗位更主动地设计后续面试方向。

| 自我介绍中的一句话 | 希望被追问 | 准备内容 |
| --- | --- | --- |
| 独立负责 Kubernetes 相关工作 | 集群、发布、故障 | K8s 实践 |
| 优化告警体系 | 指标、阈值、告警治理 | Prometheus |
| 做过自动化工具 | 架构、输入输出、异常处理 | Python / Go |
| 负责核心业务稳定性 | 故障案例、SLA、影响面 | Incident |
| 推动 CI/CD 改造 | 发布流程、回滚、审批 | Jenkins / GitLab |
| 做过云迁移 | 架构、资源、成本 | 云平台 |

和初级岗位一样：

> 不要埋自己接不住的 Hook。

但中级岗位应该尽量让 Hook 指向：

> **你真正独立负责过的事情。**

## 九、建议准备 90～120 秒版本

中级岗位通常可以稍微比初级展开一些。

### 60 秒版本

适合快速开场：

```text
职业定位
+
主要负责范围
+
1 个代表项目
+
当前方向
```

### 90～120 秒版本

推荐作为默认版本：

```text
职业定位
+
2～3 个能力变化
+
1～2 个项目证据
+
自动化 / 标准化思考
+
当前发展方向
```

通常不建议超过 3 分钟。

如果某个项目值得深入，应该留给后续追问，而不是在开场全部讲完。

## 十、一个适合中级岗位的通用框架

这不是标准答案，只用于整理自己的经历。

```text
1. 我目前主要负责什么

2. 哪些系统 / 项目是我能够独立负责的

3. 我经历过哪 2～3 个关键能力变化

4. 哪些真实项目能证明这些变化

5. 我遇到复杂问题时通常怎么处理

6. 我有没有把重复问题变成自动化、标准化或平台能力

7. 我现在希望继续往什么方向成长
```

## 十一、常见反模式

### 1. 仍然停留在初级岗位表达

```text
领导让我做什么，我就做什么。
```

如果有 4～5 年经验还一直这么表达，会让面试官怀疑独立性。

### 2. 项目很多，但没有负责边界

```text
做过 Kubernetes、ELK、Prometheus、CI/CD、Kafka……
```

中级岗位更应该说明：

> 哪些是你真正负责的。

### 3. 只讲工具，不讲问题

```text
我使用 Grafana、Prometheus、Alertmanager。
```

应该进一步说明：

> 为什么需要这些东西，以及解决了什么问题。

### 4. 只有执行，没有判断

```text
按照方案进行了迁移。
```

面试官会继续问：

> 方案是谁定的？你参与过哪些判断？

### 5. 强行包装成高级岗位

例如：

> 我负责公司整体技术战略和组织效能建设。

如果事实只是负责某个项目，会严重降低可信度。

### 6. 没有任何改进意识

工作几年后如果所有事情仍然是人工重复执行，很容易被认为停留在执行层。

## 十二、写完以后怎么自查

- 面试官能否知道我目前主要负责什么？
- 是否看得出我已经能够独立承担一块工作？
- 是否有 1～2 个项目能够证明这种独立性？
- 我有没有讲清楚“为什么这么做”？
- 是否体现了一定的业务理解？
- 是否有真实的问题排查经验？
- 是否体现自动化、标准化或持续改进意识？
- 项目里哪些是我的判断，哪些是团队决定，是否边界清楚？
- 有没有为了显得高级而扩大职责？
- 我的 Hook 是否指向真正熟悉的领域？
- 是否能控制在约 90～120 秒？

## 十三、中级岗位的核心成长方向

中级岗位最关键的变化通常不是：

> 学会更多工具。

而是：

```text
从执行任务
    ↓
独立负责结果
    ↓
形成解决问题的方法
    ↓
减少重复问题
```

因此，中级岗位自我介绍最终应该让面试官形成这样的判断：

> **这个候选人已经不是只能接受任务的执行者，而是可以把一块工作交给他，并期待他自己把事情推进到结果。**

最终可以记住三句话：

> **中级岗位最重要的是“独立负责”。**
>
> **独立负责是主线，项目是证据，方法沉淀是结论。**
>
> **不仅要告诉面试官你做过什么，还要让他看到你为什么这样做，以及你后来如何让同类问题更少发生。**
