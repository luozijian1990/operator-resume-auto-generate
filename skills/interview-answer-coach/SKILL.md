# Interview Answer Coaching

核心原则：**展开已有思考，不虚构经历（Expand reasoning, never invent experience）**。本 skill 做单题纵向分析，不替代 `mock-interview` 的实时面试，也不替代 `interview-summary` 的跨场聚合。

## 入口与取证

### 即时模式

当用户给出题目和自己的回答时，直接分析；缺少题目或原回答时只询问缺失部分。把用户明确说出的内容和根据语义可合理推导的关系分开标记。

### Replay 模式

用户指定某场面试或 Q 编号时，读取对应 `interviews/{date}-{jd-slug}.md`。只读原始记录，提取题目、L1/L2/L3 回答、卡壳原话和评分。记录为 `completed` 或 `aborted` 时不得修改它。

如果用户明确要求保存结果，写到 `coaching/`，遵循 `coaching/SCHEMA.md`；未明确要求保存时只在回复中输出分析，不创建文件。即时输入的 front matter 用 `source: ad-hoc`，来源于记录用 `source: mock` 或原记录的 `source`，不伪造 interview id。

### Replay 失败分支与检查点

- 找不到指定记录 → 列出 `interviews/` 中可匹配的文件并停止诊断，不猜题目或来源。
- 找到多个候选记录 → `CHECKPOINT · 来源确认`：列出文件名，等待用户选择后再分析。
- 指定 Q 编号不存在 → 展示该记录实际 Q 编号并停止，不替换成相邻题目。
- 记录缺少 L2/L3 或字段格式不完整 → 标记“证据不可用”，只分析已有层，不能据缺失推断不会。
- 用户粘贴回答与记录内容冲突 → 分开标注两类证据，不合并成一段经历。

保存前使用 `CHECKPOINT · 保存确认`：确认来源、题号和 `gap_types`；若元数据不足，保留 `null` 或先询问，不补造。

## 诊断顺序

先列证据，再下判断。每个判断尽量引用原回答或 `[interview_id Qn Ln]`。

1. **已覆盖**：用户明确说出的事实、判断、取舍。
2. **合理展开**：原话已经暗示、但没有说出中间关系的推理。注明“基于原话的架构推演，不等同于用户明确陈述或真实经历”。
3. **真正缺失**：回答和追问中都没有体现的知识、指标、边界或验证方式。不要把“没说出来”直接归为缺失。
4. **问题性质**：允许并列标签：`knowledge-gap`（明确不知道或追问仍不能回答）、`lack-hands-on`（明确知道原理但未做过）、`lack-edge-thinking`（常规场景会，边界追问断）、`expression-gap`（知识明显高于初答呈现）、`compressed-reasoning`（A→D，省略 A→B→C）。一次短回答只能写“本题存在压缩迹象”，不能据此形成稳定人格判断。

初答短、追问后候选人自行补齐且内容正确，优先判断为 `expression-gap`；若需要面试官提示关键答案，或追问仍不会，才偏向知识/实操缺口。能答日常场景但边界题断答，才标 `lack-edge-thinking`。混合问题保留多个标签。

## 推荐回答结构

根据题型选择结构，不强套 STAR：

- 系统设计：场景 → 约束 → 指标/流量模型 → 瓶颈 → 方案 → trade-off → 兜底 → 验证
- 故障排查：现象 → 影响面 → 快速止血 → 分层定位 → 根因 → 修复 → 防复发
- 项目经验：背景 → 问题 → 我的职责 → 决策 → 实施 → 结果 → 复盘
- 技术原理：是什么 → 为什么 → 怎么工作 → 何时用 → 边界

30 秒版和 90 秒版必须是同一套思路的不同展开程度：30 秒保留观点和三个核心层次；90 秒补充场景、约束、链路瓶颈、兜底和验证。不得把“真正缺失”中的新知识直接写成候选人已经会说的事实；可以在回答版本中加入通用方法，但要用“建议补充/如果适用”明确标注。不得加入用户未提供的项目、数字、职责或工具；不确定处用占位追问。

## 输出模板

```markdown
# Interview Answer Coaching
## 原问题
## 原始回答
## 一、你已经回答到的内容
## 二、已有但表达过度压缩的推理
## 三、真正缺失的内容
## 四、问题性质
## 五、推荐回答结构
## 六、30 秒回答版本
## 七、90 秒回答版本
## 八、面试官可能继续追问
## 九、本题训练目标
```

输出中明确区分“用户没说出来”和“用户确实没想到”。回答版本只重排和展开已有内容；新增知识单列在“真正缺失”或训练目标中。不要生成标准答案词库，不要用一句短答推断跨场能力。

## 反例与黑名单

- 不把短答直接诊断为 knowledge-gap。
- 不把架构推演改写成线上经历、职责或容量数字。
- 不把 30 秒版和 90 秒版写成两套标准答案。
- 不在 `interviews/` 写回 Coaching 结果。
- 不因单题结果修改跨场长期画像。

## 与其他 skill 的边界

`mock-interview` 只负责真实节奏、追问和原始记录；不要在面试中插入 coaching。`interview-summary` 只在多场证据重复出现时把 `expression-gap` / `compressed-reasoning` 纳入长期画像；单个 coaching 文件不改变 summary 的结论。
