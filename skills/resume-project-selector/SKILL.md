# JD 项目组合推荐

帮助用户决定“本次投递选哪些项目、为什么选、各自证明什么”。产出可供简历改写使用的选择方案，保留项目事实与来源，不直接把建议变成已完成的经历。

## 输入与范围

需要一份完整目标 JD，以及用户指定的候选项目材料。材料可以是多个 Markdown 文件、一个目录、多份简历或粘贴文本；不要求先转换格式或建立数据库。

- 支持 BOSS 岗位助手导出的 JD JSON。包含多个岗位且用户未指定目标时，列出岗位供选择，不默认取第一条或混合不同 JD；用户明确要求批量时，逐岗位独立推荐。
- 只有公司名、职位名或无法读取的链接时，请求补充完整 JD，不猜测招聘要求。
- 用户指定目录时，可读取其中相关项目材料；没有指定素材范围时，先列出 `resumes/` 中候选路径供选择，不擅自把全部历史简历混在一起。`Example/`、项目模板和能力模型不属于用户经历。
- 可选输入：简历篇幅、项目数量上限、必须保留或排除的项目、目标级别，以及用户提供的项目自查评估。已有明确约束直接沿用。
- 没有篇幅约束时，可先按 2–3 个主项目提出方案并说明假设，不为凑数量加入弱项目。只有一个项目时，说明无法比较组合，仍可判断其与 JD 的对应关系。

缺少 JD 或候选材料等关键输入时，先请求缺失内容；局部缺少规模、指标等信息时，继续分析并标记未知，只追问可能改变选择的事实。

## 整理候选项目

从原材料提取足以支持取舍的信息，保留文件路径与章节或原文定位：

- 项目身份：名称、时间、所属经历；生产工作、个人实践、学习实验或未完成计划。
- 业务问题与目标、本人职责及贡献范围。
- 已实施的行动、技术决策与取舍、规模和复杂度。
- 已有成果证据、尚待确认的内容。

同一项目的技术视角、业务视角和不同简历版本是同一个候选项目，不能重复计数。身份不明确时标记“疑似同一项目”，避免重复推荐；不同版本职责、规模或成果冲突时列出差异，不挑最漂亮的数据，也不默认最新版本就是真实版本。

保留“参与、负责、主导”等原始职责边界。只列在技术栈中的工具不等于已实施经验；项目名称不能代替行动与结果证据。用户没有提供量化数据时，可使用已有定性成果，不因缺少数字就认定没有价值。

## 分析 JD 与项目组合

先区分 JD 明确的必须项、主要职责、加分项和表述不清的要求。对岗位重点的推断单独注明，避免把技术词出现次数当作重要程度。

建立“JD 要求 → 项目事实 → 来源”的对应关系，区分直接证据、可迁移经验、信息未知与已确认缺口。个人实验可以证明实践，但不能证明生产规模或生产责任；计划不能作为已完成成果。

选择组合时综合判断：

- **相关性与深度**：是否证明岗位核心职责、所需技术深度和责任范围，而非只命中工具名。
- **证据可信度**：是否有明确个人行动、决策和结果；哪些判断仍有待核实。
- **互补性**：每个新增项目是否覆盖其他入选项目尚未证明的关键能力。内容相似的项目，比较独有贡献后决定保留、缩写或替换。
- **篇幅收益**：优先把有限空间留给强证据；遵守用户指定的必选、排除和数量约束，说明约束带来的覆盖缺口。
- **时间与实践性质**：结合相关性考虑经验是否仍适用，不机械淘汰较早项目，也不因 AI 等热门标签自动优先。

先形成首选组合，再检查整体仍缺什么、是否重复、有没有值得替换的备选。需要备选时，说明具体替换对象和成立条件，不罗列所有可能组合。

默认使用定性判断及证据，不生成看似精确的录用概率或单项分数。项目组合比较不等于完整简历匹配度评分；用户另需完整简历评分且仓库中存在 `shared/match-scoring.md` 时，沿用该契约，不另造口径。

若提供了项目自查评估，可辅助指出面试准备风险。未自查、未回答不等于不会；表达不充分也不直接等于没有实践。即使所有项目都较弱，也如实给出有限建议和缺口，不宣称已经匹配。

学历、年限等明确门槛单列，不能被项目组合“抵消”；本环节不代替完整投递决策。

## 输出建议

先给推荐结论，再给足以检查和调整的依据。可按材料规模精简，默认包括：

1. **推荐组合与假设**：选哪些项目、顺序、每项详写或简写，以及采用的篇幅约束。
2. **入选依据表**：项目、对应 JD 要求、项目事实及来源、表达重点、证据不足之处。
3. **组合取舍**：各项目新增证明了什么；其余候选项目为什么备选或不展开。明确“不适合这次篇幅”不代表项目没有价值。
4. **仍未覆盖的要求**：分别列出真实缺口、材料未体现和待澄清事实。只问会影响本次选择的关键问题。
5. **改写交接提纲**：目标 JD 来源、入选项目原始来源、顺序、每项应强调的已有事实、不得升级的职责或成果边界。

表达重点只改变已有事实的组织方式。例如突出发布治理时，可以前置真实实施过的回滚、审批和验证；不能因为 JD 要求 GitOps，就把 Jenkins 经历改成 Argo CD 落地。

默认在对话中返回建议，不修改原始素材或自动生成完整投递版简历。用户要求保存报告时，写入指定位置；未指定时使用 `resumes/project-selection/{日期}-{岗位标识}.md`，重名追加版本号，保留原件。

## 衔接现有流程

组合得到用户认可后，若用户希望继续改写，使用交接提纲与原始材料衔接可用的 `resume-optimizer`；不得只凭本报告摘要补齐完整简历。用户已明确授权按推荐组合继续生成时，不重复询问同一授权。

项目自查或模拟面试是可选后续，不作为推荐项目的前置条件。本 Skill 可独立接受导出的 JD 和本地材料，不依赖浏览器插件、API Key 或其他 Skill 才能完成选择分析。
