# 回答评分与报告规则

## 先确定范围和题目有效性

明确评估哪些项目、哪些问题及使用的简历版本。用“项目 / 视角 / 第 N 题”和问题原文定位，引用回答时保留原意，不能把建议补充内容当成已答事实。

先基于项目明细确定核心问题，不根据答得好不好事后改变核心题。每个项目通常关注：业务目的与影响、个人职责、主要实施链路、成果与验证；项目确实涉及故障、发布、数据或资源变更时，还要关注对应恢复或验证方法。只选题单已有且有项目依据的问题，不新增考试要求。题单未覆盖必要核心内容时标记“题单覆盖不足”，不能因此扣答题分。

## 状态与分数

每题只能属于以下一种状态。共 N 题应满足 `N = S + U + C + X`。

| 状态 | 计数 | 分数 | 处理 |
| --- | --- | --- | --- |
| 已评分 | S | 1—5 | 有可判断内容，含明确表示“不会” |
| 未回答 | U | 不计分 | 空白、只有“回答：”、TODO、待补充等占位 |
| 待澄清 | C | 暂不计分 | 有实质回答，但缺关键条件或存在事实冲突，无法可靠判断；列出具体澄清点 |
| 题目不适用 | X | 不计分 | 题目超出项目依据、技术仅在列表出现、或题目错误预设候选人做过某事 |

部分回答只要可判断，仍应评分并说明局限，不能为避免低分而全部标为待澄清。已能确定的技术错误按评分处理，不能借待澄清隐藏；依赖未给出的版本、配置或业务约定才能判断的结论应先求证。必要时查官方资料验证具体技术主张，不把外部资料当成用户经历。

候选人主动说明“我参与配置验证，方案由同事设计”，是职责澄清，不因未主导而降分。若简历明确写主导而回答否认，列两处原文并等待解释；不能据此直接判定造假。

| 分数 | 在该题范围内的判断 |
| --- | --- |
| 1 | 明确不会、严重跑题或核心理解明显错误 |
| 2 | 有相关认识，但关键环节缺失或有明显错误，尚不能说明怎样完成该工作 |
| 3 | 主要思路基本正确，能回答核心问题，实践依据或验证说明仍不足 |
| 4 | 解释清楚，关键操作、依据与验证有具体支撑，个人职责明确 |
| 5 | 该题需要的事实、依据、结果和必要取舍充分且一致，能自洽地解释实际做法 |

分数不是按篇幅、命令数量、关键词或 STAR 格式计算的。简单事实题简短完整也可得 5 分；不是所有题都要事故案例或复杂取舍。技术题侧重机制和实施验证；业务题侧重真实场景、影响、协作及效果依据。不另造四项加权总分。

逐题点评包含：状态和分数、原回答证据、评分理由、需要补充/澄清的具体内容。明确标注“未体现”与“明确不会”的区别。补充建议可以给核实方向，不能替用户填入项目事实、工具、数字或职责。

## 统计

每个项目的每个视角均列一行；用户选定范围内未填写的题也必须计数。

- 适用题数 `A = N - X`。
- 回答覆盖率 `(S + C) / A`：表示有实质回答，不代表已经答对；明确“不会”也算已回应。
- 可评分覆盖率 `S / A`：与回答覆盖率一起展示，避免大量待澄清被误认为准备充分。
- 已评分均分 `sum(scores) / S`，保留一位小数。未回答、待澄清和不适用均不作为 0 分或 1 分加入均值。
- `A = 0` 时两个覆盖率显示 N/A；`S = 0` 时均分显示 N/A，不除零，不给满分。汇总均分按所有已评分题计算，不平均各组均分。
- 同时报告 N、S、U、C、X 和核心问题状态。除上述口径外，不混用百分制、岗位匹配分或能力等级。

## 准备度建议

先判断证据是否足够，再给建议。以下是理由框架，不是保证通过的数学门槛。

| 建议 | 适用证据 |
| --- | --- |
| 建议进入 | 原简历已核对；全部选定项目的业务、技术核心问题均有可判断回答；关键内容至少基本正确且有实施/验证支撑；无未澄清的重大矛盾；其余缺口不会影响主要项目叙述 |
| 补强后进入 | 项目主线基本清楚，但关键操作、个人贡献、成果口径或验证仍欠缺；能指明需要优先补的具体题目 |
| 建议先继续项目自查 | 多个核心问题未回答，或主要机制明显错误，或核心经历存在尚未澄清的矛盾；明确区分覆盖不足和答错，不宣称整体能力差 |

仅回答少量题、仅答一个视角、缺原简历或题单缺少核心覆盖时，标记“阶段性评估，整体准备度暂不能判断”。仍可对已答部分给补强方向，但不能输出全局“建议进入”。用户明确只评一个项目时，可以给该项目的建议，不能推及其他项目。

不要用高平均分掩盖关键的恢复流程不会、个人贡献不明或成果口径矛盾。也不要因为非核心题未全部填满就机械禁止进入下一阶段。所有建议均为可选，用户仍可直接选择 JD 模拟面试。

## 独立报告模板

报告不是脑图题单，可以使用表格和说明章节；不要写回回答文件。保留所有题目的状态，不只展示答得好或差的题。

下一步按具体缺口提出建议：表达压缩可选单题辅导；知识、实操不足先补课练习；事实矛盾先核实；空白题先尝试作答；不适用题先纠正题目依据。可以建议用 `interview-answer-coach` 进一步诊断，但不因低分直接认定表达问题，也不自动启动辅导。交接需保留原题单路径和“项目 / 视角 / 第 N 题”，报告只作辅助。

用户训练后提交自己的新回答，才按本规则重新评分并生成新版报告；不使用 coach 的推荐回答替代用户补答，不因完成辅导而自动提分。

```markdown
# 项目自查回答评估

## 来源与范围

- 题单/回答文件：{路径或粘贴来源}
- 原简历：{路径与核对范围，或未核对原简历}
- 评估日期：{日期}
- 选定项目：{项目列表}
- 评估范围：{整体或阶段性及原因}
- 本报告不涉及 JD 匹配，依据当前书面回答评估。

## 准备度建议

{建议类别或整体暂不能判断；引用具体核心问题支撑；提醒建议不构成强制准入。}

## 覆盖与评分汇总

| 项目 | 视角 | 总题数 N | 已评分 S | 未回答 U | 待澄清 C | 不适用 X | 回答覆盖率 | 可评分覆盖率 | 已评分均分 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |

## 核心问题状态

{列出各项目核心问题、选择依据与当前状态，不新增没有项目依据的要求。}

## 逐题评估

### {项目名} / {视角} / 第 {N} 题

- 问题：{原题}
- 状态 / 分数：{已评分 3/5，或未回答/待澄清/题目不适用且不计分}
- 回答证据：{原话短引文；空白则如实说明}
- 判断依据：{已覆盖什么，哪里未体现或存在错误；相关简历原文}
- 建议补充：{具体且不代写经历；无必要补充可写无需补充}

## 优先补充项

{按影响排序，关联具体题目，说明需要找什么事实、证据或澄清什么。}

## 下一步

{根据缺口选择：继续填写、核实事实、补课练习，或指定题目交给 interview-answer-coach。列出题单路径、项目 / 视角 / 第 N 题与训练理由；用户重新作答后生成新版评估。用户也可直接选择 mock-interview，后者另需完整 JD 和简历；均不自动启动。}
```
